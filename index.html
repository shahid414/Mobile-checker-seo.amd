What is a mobile-friendly test?

A mobile-friendly test checks whether a website works well on a phone: does it fit the screen without sideways scrolling, is the text readable without zooming, and can visitors tap links and buttons easily? This tool fetches your page the way a phone browser does and checks the real page code — viewport tag, responsive CSS, font sizes and layout risks.

Why mobile usability matters

  • Mobile-first indexing: Google ranks your site mainly from its mobile version.
  • Rankings: pages with mobile usability errors can rank lower than mobile-friendly competitors.
  • Visitors: most web traffic is on phones — a page that is hard to use on mobile loses visitors fast.

What this tool checks

Every test runs the same seven checks. Each check carries a weight — the score is the sum of the checks you pass (a warning counts as half).

Viewport tag · 30 pts

Is width=device-width set, so phones render the page at the right width?

Responsive CSS · 20 pts

Are there media queries in the page or its stylesheets, so the layout adapts?

Font size · 15 pts

Is the smallest text at least 16px, readable without zooming?

Horizontal scroll risk · 15 pts

Any fixed widths of 900px or more that can spill off a phone screen?

Pinch-to-zoom · 10 pts

Can visitors zoom in, or is zoom locked by the viewport tag?

Title & H1 · 10 pts

Does the page have a title tag and one H1 heading?

After the static result, a real-browser check (Chromium, 390px phone screen) measures actual overflow, tap targets, font size and layout shift — rows marked RENDERED. Google Lighthouse (PageSpeed Insights) now only covers performance and CLS, not tap targets or font sizes.

Common mobile usability problems

  • Missing viewport tag — phones render the page at desktop width and shrink it.
  • Content wider than the screen — fixed-width elements force sideways scrolling.
  • Text too small to read — visitors must pinch-zoom every paragraph.
  • Clickable elements too close — buttons and links that are hard to tap accurately.
  • No responsive CSS — one fixed layout for every screen size.

How to improve your score

  1. Add <meta name="viewport" content="width=device-width, initial-scale=1"> to every page.
  2. Use responsive CSS with @media queries and fluid widths (max-width: 100%).
  3. Set body text to at least 16px and keep tap targets at least 48px apart.
  4. Re-test after each fix — then check your most-visited pages the same way.

How to read your results

  • 80–100 — Mobile friendly: the page passes the checks that matter.
  • 50–79 — Needs work: fix the failed checks listed in the recommendations.
  • Below 50 — Not mobile friendly: the page likely has a missing viewport or no responsive layout.
